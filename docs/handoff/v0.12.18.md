# v0.12.18 — an Excellent pad replays the mix that was rated, not the plain fade (21/10)

**The owner (21/10):** a mix he rated Excellent was saved as a "Mix in" pad, but pressing the pad "switches really fast, not slowly and elegantly" like the mix itself.

**Cause:** the pad kept only the second B started at (`HotCue.positionSec`). `pressHotCue` always ran the plain transition (`startAutoTransitionOnPhrase`, a fixed 5 s fade, `TRANSITION_CROSSFADE_SEC`), whatever mix had been rated. A vocal handoff runs for bars, following A's position, so it came back as a cut.

**Built:**
- `HotCue.mix` (`core/types.ts`): `{type: 'handoff' | 'swap', voiceSec}`, B's voice line the row was planned on. Absent = plain mix, which covers every pad saved before.
- The handoff and swap row starts tag the running transition (`markReplay`). `finishTransition` carries the tag into `pendingMixRating.mix`, and the Excellent save puts it on the pad.
- Pressing such a pad finds the same voice line in B (`bVoiceStarts` / `swapEntries`, within 0.5 s) and runs that row (`startVocalHandoffAt` / `startVocalSwapAt`). It is judged as the row is: the handoff gets the panel's length check (`enoughSongAfterMix`) and the swap gets `swapEntries`'s, not the plain mix's 24-bar rule counted from B's start, which refused a handoff that the row itself runs. Only a transition that really started is tagged: a refused start leaves the old one untagged.
- If B's marks changed and the line is gone, the plain mix runs and a warning says it is not the rated mix.
- "Keep" on the already-Excellent prompt (v0.12.15) teaches an existing pad at that point its mix. This is the way to fix an old pad without rating again. Rating the same point Excellent after a different mix, a plain one included, updates the pad to the latest one. The fallback warning shows only when the plain mix did start.

**Verified:** `scripts/verify-vocal-handoff.mjs` 49/49, 4 new checks:
- the rating and the pad carry the handoff;
- pressing the pad runs a handoff (`handoffSec` set, not `onPhrase`);
- "keep" fills an old pad;
- a missing line falls back with the warning.

There is no browser check of the swap path of the replay. `scripts/verify-vocal-swap.mjs` fails 4/12 on the base as well (debt in `HANDOFF.md`). The swap path is the same lookup, against `swapEntries`.

**Not changed:** an excellent pair replayed from the library (`startAutoTransition` with the saved exit second) still runs the plain fade.
