# v0.12.14 — a mix rated Bad stops coming back (21/10)

Shalom: "once I mark a mix between two specific songs as BAD, it should not keep appearing, and a different, better mix should be offered instead."

## What was wrong
`rateMixTransition('bad')` cleared the prompt and stored nothing (`mix-ratings-idb` said no behaviour read a negative rating). Mix Assist's panel therefore offered the same row again next time.

## What was built
- `core/bad-mixes.ts`: a bad mix = pair (outgoing hash -> incoming hash) + the incoming song's entry second, matched within 4 s (`SAME_BAD_WINDOW_SEC`, narrower than the 8 s merge window so a neighbouring row survives).
- `platform/mix-bad-idb/store.ts`: key `deckmix:mixbad:<fromHash>`; added to `STORAGE_KEYS` in `tests/repo/product-name.test.ts`.
- `controls.ts` `saveBadMix`: stores it, removes an Excellent entry at the same point (`removeExcellentNear`), says so in a notice. Missing hash on either song is said, not skipped. `restoreBadMixes` undoes it.
- `TransitionPointsPanel`: handoff, vocal-swap and energy rows at a Bad second are left out, with a line "N mixes you marked bad are not shown" and a "show again" button; a section whose every row was hidden says so. The alternative offered is the pair's other rows, unchanged.

## Not done, said plainly
Only the pair's own rows in the panel are filtered. A different *song* is not suggested by the Bad rating itself (the library recommender still ranks as before). The "small experiment first" rule: BAD was never stored, so there was no real data to test against; the feature is a filter over an existing list, and the first real check is the owner's.

## Check
`tests/core/bad-mixes.test.ts` (window, refresh, hiding, count, Excellent removal). Not run in a browser: needs two analysed songs and a finished mix.

## Follow-ups (21/10, same day)
- An Excellent point is never removed or hidden by a Bad; Mix Assist lists it first with a star and the accent pill.
- A mix whose entry point is already saved as Excellent no longer asks "how did it work": the prompt says it was already rated and offers Keep (no change) or Remove Excellent (the only way the rating goes). The lookup is async, so the normal prompt opens first and switches when it lands.
