# v0.9.39 — רשימת השירים נשארת איפה שגללת (באג, שלום 06/10)

## מה שלום דיווח
"אם פילטרתי לפי ז'אנר ואז גללתי למטה בשירים ובחרתי שיר לדק מסוים ולאחר מכן לחצתי PLAY ואז PAUSE או שהשיר
נגמר — הרשימה פשוט קפצה למעלה. אני רוצה שהרשימה תמיד תישאר איפה שגללתי אליה."

## הסיבה
באותה תיבת גלילה הטבלה מציגה שלוש רשימות שונות: כל הספרייה, ההצעות של Mix Only (נדלק לבד כששיר מתחיל
לנגן ונכבה כששניהם נעצרים), ו-"More like this". הקוד הקודם (`Library.tsx`) שמר **מספר אחד** — מקום הגלילה
האחרון שנראה כשהיו שורות — והחזיר אותו אחרי החלפה אוטומטית.

המספר הזה נדרס בדרך פנימה: רשימת ההצעות קצרה (למשל 5 שורות), הדפדפן חותך את 2000px ל-0 ושולח על זה
אירוע `scroll` — ו"המקום הטוב האחרון" הפך ל-0. לכן PAUSE (או סוף שיר) החזיר 0 לספרייה המלאה: קפיצה למעלה.

## התיקון
- `src/core/scroll-memory.ts` — מודול טהור: מקום גלילה **נפרד לכל תצוגה** (`all` / `mix` / `similar:<id>`).
  כל עוד שחזור ממתין, אירועי גלילה הם חיתוך של הדפדפן או השמה של הקוד — לא יד של שלום — ולכן לא נרשמים.
  נגיעה שלו (גלגלת, לחיצה, מקש) מבטלת שחזור ממתין מיד, כדי שהשחזור לא ייאבק עם היד שלו.
- `src/app/hooks/useScrollMemory.ts` — חצי ה-DOM: המאזינים, ושחזור בכל commit של ההחלפה (חלון השורות
  הווירטואלי מתעדכן רנדר אחרי הרשימה, אז ההשמה הראשונה נחתכת), עם ויתור אחרי 800ms.
- `Library.tsx` — שורה אחת במקום שני אפקטים ושני refs.

## מה נבדק
- `tests/core/scroll-memory.test.ts` — 5 בדיקות, הראשונה היא הרצף של שלום בדיוק.
- `npm run check` ירוק: 92 קבצי בדיקה, 1336 בדיקות (06/10).
- בדיקה בדפדפן אמיתי (Playwright + Chromium, ה-hook האמיתי מול רשימה וירטואלית של 400 שורות בתיבה של 300px.
  כדי להראות שהבדיקה נופלת בלי התיקון, הורץ אותו רצף עם ההתנהגות הישנה — מספר אחד לכל התצוגות):

  | שלב | התנהגות ישנה | אחרי התיקון |
  | --- | --- | --- |
  | גלילה ל-2000 | 2000 | 2000 |
  | PLAY → הצעות (5 שורות) | 0 | 0 |
  | PAUSE → ספרייה | **0 — הבאג** | **2000** |
  | גלילה ביד בזמן שחזור | 500 | 500 |

  0 שגיאות קונסולה, 0 שגיאות עמוד. עמוד הבדיקה היה זמני ונמחק; מה שנשאר נבדק הוא ה-hook עצמו.

## איך שלום בודק
1. לסנן ז'אנר, לגלול למטה ברשימה, לטעון שיר לדק.
2. PLAY, ואז PAUSE (או לחכות שהשיר ייגמר).
3. הרשימה צריכה להישאר בדיוק איפה שהייתה. אם היא קפצה למעלה — שבור.
